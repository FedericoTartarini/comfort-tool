# Coding standards

Read by `/code-review`. Rules a machine can check live in `eslint.config.js`, `tsconfig.json` and the tests, not here (see `docs/code-quality-checklist.md`).

## Architecture

- `routes/navigation.ts` is the only sv-router usage. `ui/primitives/` is shadcn-svelte generated: do not hand-edit it.
- The lint rule on library model functions bars the package root only: v2's `exports` map adds `jsthermalcomfort/models` and other subpaths, which it does not bar, so check those imports by hand until the Vite+ migration.

**Canonical state is always SI.** The library is always called in SI, even though it supports IP — one path only: declarations write no `units`, so the library's SI default applies. Conversion happens at the display boundary in `core/units.ts`. A slot holds the full-precision SI number; nothing written into one is rounded. The gate compares a value and its bound's ends at the formatter's precision in the quantity's SI display unit (`gateUnitFor` in `core/applicability.ts`), so a difference no row shows never closes it (ADR-0002 decision 56). The app's IP display units (fpm for air speed) differ from the library's IP calling units (fps), so the library's `ipUnit` strings and `units_converter` are never read.

**No duplicated definitions.** Quantities, models, standards, units, pages, chart types and an Image's sizes and formats (`core/image.ts`, which have no `id`: they are in no link) are objects referenced by identity (`quantities.tdb`, `chartType.dynamic`), never string keys and never `Record<string, …>` dictionaries. Wire strings are defined where their objects are: `core/quantities.ts` (the `key` column, reconciled with the library's `_INFO` by a drift test), each option's `key` in its model's declaration (the library kwarg it feeds, proved by a registry-wide test; ADR-0002 decision 36), each closed set's `id`, and a model's name, which the library's model info gives. Only `core/shareLink.ts` turns objects into those strings and back (ADR-0002 decision 63); it also writes the field names of `ValueEntryModes` as `entryModes`' members, so renaming one changes the format. The share parameter's name (`routes/navigation.ts`) and the tab's storage entry (`state/keptText.ts`) are transport names, not ids. Nothing looks an option up by its key. The app's and the library's versions are two build constants, `__APP_VERSION__` and `__LIBRARY_VERSION__`, defined in `vite.config.js` from the two package files and declared in `src/buildConstants.d.ts`; no version is typed into the source. `Quantity.kind` is the app's string union used as a typed discriminant (`core/units.ts` looks up display units by kind with an exhaustive `satisfies Record<QuantityKind, …>`).

**Calculation ownership: four rules, applied in order** (ADR-0002 decision 21).

1. pythermalcomfort has it → jsthermalcomfort must have it. The gap is the lead's roadmap; when a phase needs an item, port it upstream first on the branch `package.json` names and consume the rebuilt `lib/esm`. Never a copy in the app, under any name.
2. jsthermalcomfort has it → import it. Applicability bounds, classifiers, standards, reference tables, psychrometrics: read, never transcribed.
3. Neither has it and it is a standalone calculation (pure SI in, SI or geometry out, reading no label, unit, colour, route, slot or `Quantity`) → `src/temporary-library/`, written to the library's conventions for a helper (snake_case functions and locals, CONSTANT_CASE for a constant it adds, positional scalar arguments, a `TypeError` naming a wrong-typed argument, NaN passed through by a member that calls no model, frozen results, TSDoc with nothing about the app, library-shaped tests; ADR-0002 decision 90 rule 12) so the move upstream is a file cut. Adaptive's zone geometry and the inverses of the two activity corrections live there.
4. Everything that reads a label, unit, colour, route, slot or `Quantity` → app (`core/`, the declaration file, `ui/`). Defaults, input order, entry-group conventions (`tdb = tr = operative_tmp`, `v → vr` via `v_relative`), violation sentences, the app's own labels, a standard's route segment. A model's route segment is not written: it is spelled from the model info's `name`, the library's function name (ADR-0002 decision 30).

The one formula the app writes in `core/` is unit conversion for display (°C↔°F, m/s↔fpm, Pa↔kPa/inHg) in `core/units.ts`: all state is SI, only the UI converts, and the library's `units_converter` gives fps and atm, which the tool does not show. The inverses of the library's two activity corrections (`v_relative` in closed form; the clothing correction by bisection over the library's own rule) are rule 3's: `src/temporary-library/`, read by the entry-mode switch back (ADR-0002 decision 54 as revised 2026-09-30; the gate reads neither since decision 84's note of 2026-10-28).

**The library follows pythermalcomfort.** jsthermalcomfort adopts upstream's logic _and_ its naming by default (`Standard` is the one documented exception to `Models`); deviate only where TypeScript requires it, and write the reason at the site. Reference tables carry pythermalcomfort's names (`met_typical_tasks`, `clo_typical_ensembles`, `clo_individual_garments`). The app installs the library from the GitHub branch `package.json` names, pinned in `package-lock.json`, so a library change reaches it once it is on that branch and the lock is moved to it, and then this app's four scripts run, in the same pass; the PR is opened by hand, never by an agent.

**Number display.** One formatter, `core/numberFormat.ts`: at most two decimals, trailing zeros stripped (`26.0 → 26`, `0.51 → 0.51`, `78.80 → 78.8`). Input step comes from the currently displayed unit, not the SI one. The formatter's constant is the app's one precision: the gate judges at it, the bound's text reads at it, and a test of a number a person can see asserts at it; it is read from that file and written nowhere else. The one comparison, `isShownBeyond`, sits beside the formatter: the gate, the atmospheric pressure's check and `violationRows` call it through `breaksBound`, and the bound's text asks it of each end typed back, stepping one shown digit inward where the gate would stop that end (`formatBoundEnd`). No rounding at a write, and no arithmetic to make a converted value agree beyond what a row shows (ADR-0002 decision 56).

## Svelte and TypeScript

- **Runes only.** No `export let`, `$:` or `on:`: neither lint nor svelte-check rejects them. Cross-component shared state is a class with `$state` fields; **`$effect` is for external synchronisation only and never assigns to state** — anything computed from state is `$derived`, per Svelte's own [Best practices](https://svelte.dev/docs/svelte/best-practices). Lint enforces the no-assign rule only in `state/` and in pages. Keeping a last valid value across an invalid input is served by a plain (non-rune) field holding the derivation's own last output, not by an effect.
- **Identity survives state.** Objects compared by identity (models, quantities, closed-set members) are held in `$state.raw`, never a deep `$state` proxy, and are replaced rather than mutated. A proxy breaks `===` against the library's objects (`session.unitSystem === unitSystem.si` silently false).
- **Closed sets.** Closed sets are `as const` objects of plain data objects with a derived union type, the same shape as the library's `io.quantities` (`page.explore`, `temperatureMode.operative`). Behaviour is a plain function (`pagesOf(model)`), never a class hierarchy; an id is looked up in one place, privately in `core/shareLink.ts`, and no closed set exports an `xxxFromId()` (ADR-0002 decision 63). State containers (`Session`, `InputSlot`) stay runes classes.
- **Naming.** Components `PascalCase.svelte`, modules `camelCase.ts`, a function that acts or answers a question starts with a verb, one that only returns a value is named for what it returns, a noun phrase, with a preposition where the name must say what it is read from or made of, `…For`, `…Of`, `with…` or any other (`violationRows`, `displayUnitFor`, `labelWithUnit`), a conversion `to…`, a callback `on…` after its event. A closed-set table or palette is `camelCase` (`chartType`, `palettes`) so it reads like the library's `io.quantities`. Never `engine` / `manager` / `helper` / `utils` as a filename. No abbreviations except library quantity keys. A quantity's label always comes from `Quantity.label`; the app never writes one. The old tool's "Air temperature" was wrong and is not carried over; the library says "Dry-bulb air temperature". `temperatureMode` decides which quantity is shown and which is the temperature axis (`tdb` or `operative_tmp`), so axis labels switch with it for free.
- **Granularity.** One concept per file, 100–400 lines is normal. Plain functions over class hierarchies. Do not abstract for a second caller that does not exist.
- Declare component props as a named `interface Props` above the `$props()` destructuring. Complex `{#if}` conditions go in a `$derived`.
- Use shadcn-svelte primitives first.
