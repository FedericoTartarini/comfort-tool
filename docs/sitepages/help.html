Help

How to get an answer out of the tool, and what to do when the answer looks wrong.

Getting an answer in four steps

  1. Pick a workspace. Four are compliance workspaces, one per standard. Explore is for open-ended investigation, Time-series for exposure over time.
  2. Pick a model from the model selector, if the workspace offers more than one. ASHRAE 55 offers PMV and Adaptive; the others open on a single model.
  3. Enter your inputs in the panel. Results update as you type there is no calculate button.
  4. Read the result and the chart. The result table gives the number and the verdict; the chart puts it in context against the bands.
The tool runs entirely in your browser. There is no account to create, nothing is uploaded, and closing the tab discards the session. To keep a calculation, copy a share link before you leave.

Reading a URL

Workspace addresses are readable, and a link can point at an exact model rather than just a workspace:

Pattern Example
/standard/{standard}/{model}/ /standard/ashrae-55/pmv-ashrae/
/explore/{model}/ /explore/utci/
/time-series/{model}/ /time-series/phs/

A ?state= parameter on the end means the link carries a full calculation. Opening it fills in the inputs and selects the chart; the tool recalculates the results locally.

When something looks wrong

The result says “Out of range”

The model does not apply to what you entered. Check your inputs against the limits on the model's page each model has its own envelope, and they are narrower than people expect. Note the caveat about PMV in Thermal comfort questions: on the PMV models this message is currently also used for a valid but non-compliant result.

A field will not accept a value

Inputs are range-checked as you type. The accepted range for each field is listed on the model page. If the value you need is outside it, the model is not the right one for your case.

An input modifier seems to do nothing

A modifier is applied only when all of its own fields hold valid values. A partly filled modifier is ignored rather than half-applied. Check the modifier panel for an empty or out-of-range field.

The numbers changed after I switched units

They should not have, beyond rounding. The tool stores inputs in SI and converts for display, so switching to IP and back is safe. Rounding in the displayed value can move the last digit; if you see a larger shift, that is worth reporting.

A shared link opened with default values

The link was probably truncated email clients break long URLs across lines. The tool validates a link before using it and falls back to defaults rather than restoring half a calculation. Ask for it to be re-copied, and paste it as a single line.

A result disagrees with the previous version of the tool

Two common causes. Dynamic clothing used to be applied automatically and is now an explicit modifier. And PMV is now split into distinct ASHRAE and ISO models, which use different calculations check you are comparing like with like.

The chart I expected is not there

Each model declares its own charts; there is no fixed set shared across models. Most offer one or two. If you are looking for a chart you remember from older documentation, it may have belonged to a different model.

Browser support

Any current version of Chrome, Firefox, Safari or Edge. The tool needs JavaScript; Time-series additionally runs its simulation on a background worker thread, so the interface stays responsive while a long scenario computes.

Reporting a problem

Issues go to the project's issue tracker. See Contributing for where to file and what the project expects.

A report is far easier to act on with these included:

  • A share link reproducing the case, where the workspace offers one. This is the single most useful thing you can attach it carries every input, mode and chart setting exactly as you had them.
  • The workspace and model, if there is no link the URL is enough.
  • What you expected and what you got. For a disagreement with another implementation, the other tool's result and version.
  • Browser and operating system, for anything visual or unresponsive.
For a suspected calculation error, check the model page first to confirm the case is inside the model's applicability limits. Results near a limit often differ between implementations for legitimate reasons, and that context helps whoever picks up the report.
